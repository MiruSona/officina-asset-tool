## 4. AssetTool `index` (1차의 AssetTool 전부)

### 4-1. 꼴

```
assettool index --unity <Unity 뿌리> [--out <파일>] [--json]
```

- `--out` 기본 = `<뿌리>/Library/AssetTool/address-index.json`. 다른 자리에 쓰면 `unityRoot` 를 그 자리 기준으로 다시 계산해 적는다.
  **다른 드라이브면** 상대경로를 못 만드니 절대 경로를 적고 알림 한 줄 (DataTool 은 3-4 ③ 규칙으로 그런 색인을 열지 않는다).
- **쓰는 것은 `--out` 한 장뿐**이다 (tmp → 이름 바꾸기). Unity 파일은 한 글자도 안 쓴다. 쓰기 꼴은 2-1 「쓰기 꼴」 그대로.
- 종료 : 0 성공(알림이 있어도) · 1 사용법 · **4 읽기 실패·모르는 꼴(색인을 안 쓴다)** · 5 쓰기 실패.
- 알림은 stderr 에 한 줄씩, `--json` 이면 `{"ok","out","counts":{"entries","groups"},"notices":[…]}`.
- `version` 명령도 둔다 (DataTool 과 같은 꼴 — 커밋·빌드 시각·`-dirty`).
- Go 단일 exe · **바깥 라이브러리 0개**(YAML 라이브러리도 안 쓴다) · `CGO_ENABLED=0` · 상주 없음.

### 4-2. 읽는 차례

조사는 「settings → 그룹 → 항목 → .meta」 차례로 적었지만 **.meta 를 먼저 훑는다.** settings 가 그룹을 guid 로만 가리키기 때문에 guid → 경로 표가 먼저 있어야 한다.

| # | 읽는 것 | 뽑는 것 |
| --- | --- | --- |
| 1 | `Assets/**/*.meta` 한 번 훑기 | `guid` → 경로 표. 스프라이트 시트면 `spriteMode: 2` 와 `spriteSheet.sprites[]` 의 `name`·`rect` 도 |
| 2 | `ProjectSettings/EditorBuildSettings.asset` 의 `m_configObjects` → `com.unity.addressableassets` guid → **`DefaultObject.asset`**(`AddressableAssetSettingsDefaultObject`, 보통 `Assets/AddressableAssetsData/DefaultObject.asset`) → 그 안 **`m_AddressableAssetSettingsGuid`** | settings 자리. 한 단계 더 거친다. **어느 칸이든 없으면 기본 자리** `Assets/AddressableAssetsData/AddressableAssetSettings.asset` |
| 3 | settings `.asset` | `m_GroupAssets[].guid` · `m_LabelTable.m_LabelNames` |
| 4 | 그룹 `.asset` 마다 | `m_GroupName` · `m_IncludeInBuild` · `m_IncludeInBuildMigrated` · `m_SchemaSet.m_Schemas[].guid` · `m_SerializeEntries[]` 의 `m_GUID`·`m_Address`·`m_SerializedLabels` |
| 5 | 그룹의 스키마 `.asset` 들 | **`m_IncludeInBuild` 칸이 있는 스키마 전부**의 그 값과 `m_Enabled` (4-4) |
| 6 | 항목마다 | 경로 풀기 → 폴더면 펼치기 → `kind` → 스프라이트면 `sub` |
| 7 | 정렬 · `sourceMtime` · 쓰기 | 2-1 쓰기 꼴대로 tmp → 이름 바꾸기 |

②의 근거 : [AddressableAssetSettingsDefaultObject.cs](https://github.com/needle-mirror/com.unity.addressables/blob/master/Editor/AddressableAssetSettingsDefaultObject.cs) 28·47·110행 (리뷰에서 소스로 확인).

**YAML 읽기 (`internal/unityyaml`) :** Unity YAML 을 **줄 단위로** 읽는다. 알아야 하는 꼴은 이것뿐이다 —
`--- !u!114 &…` 문서 가르기 · `키: 값` · 들여쓰기 블록 목록(`- m_GUID: …`) · 한 줄 흐름 맵(`{fileID: 0, guid: …, type: 2}`) ·
따옴표 값(작은따옴표의 `''`, 큰따옴표의 `\uXXXX` — **서로게이트 쌍 `\uD83D\uDE00` 은 한 글자로 합친다**) ·
**줄을 넘겨 접힌 값은 세 꼴(따옴표 없음 · 작은따옴표 · 큰따옴표) 모두.** 그 밖의 꼴이 **읽어야 하는 칸 자리에** 나오면 종료 4.

### 4-3. 폴더 펼치기 · 스프라이트

| 규칙 | 값 |
| --- | --- |
| 폴더 항목 | 항목 guid 의 경로가 폴더면 그 아래를 **끝까지** 훑어 `폴더address/하위경로`(확장자 포함, `/` 구분)로 펼친다. 그룹·라벨·includeInBuild 는 폴더 것을 물려받는다 |
| 뺄 것 (Addressables 와 같게) | ① `.meta` 짝(guid)이 없는 것 — `.` 으로 시작하거나 `~` 로 끝나 Unity 가 임포트 안 한 것이 여기서 빠진다 ② 확장자 `.cs .js .boo .exe .dll .meta .preset .asmdef` (대소문자 무시) ③ 경로에 `/Editor/` 가 든 것 (대소문자 무시) ④ settings 폴더 아래. **`.asmref` 는 안 뺀다** |
| 겹칠 때 | 폴더 안 파일이 **자기 항목도 따로** 있으면 따로 있는 쪽이 이긴다 (같은 guid 로 판정) |
| 스프라이트 하위 | 텍스처 `.meta` 의 `spriteMode: 2`(Multiple) 일 때만 `spriteSheet.sprites[].name`·`rect` 로 `sub[]` 를 만든다. Single 이면 `sub` 없음 |
| PSD Importer (`.psb`) | `.meta` 꼴이 달라 **1차엔 `sub` 를 안 만든다** (칸에 `[이름]` 을 적으면 V10 이 `asset_sub_unchecked` 경고로 통과시킨다) |

「뺄 것」 근거 : `AddressableAssetUtility.cs` 72~124행 · `AddressablesFileEnumeration.cs` 159행 (needle-mirror 소스, 리뷰에서 대조).

### 4-4. 「빌드에 들어가나」

Addressables 4.0 은 스키마의 값을 그룹으로 옮기고 그룹에 `m_IncludeInBuildMigrated` 깃발을 세운다(`AddressableAssetGroup.cs` 의 `MigrateIncludeInBuildFromSchemas`). 위에서부터 처음 맞는 줄을 쓴다.

| # | 조건 | 쓰는 값 |
| --- | --- | --- |
| 1 | 그룹 `m_IncludeInBuildMigrated: 1` | 그룹의 `m_IncludeInBuild` |
| 2 | `m_Enabled: 1` 인 buildable 스키마(`m_IncludeInBuild` 칸이 있는 스키마)가 있다 | 그 스키마의 `m_IncludeInBuild` |
| 3 | `m_IncludeInBuild` 칸이 있는 스키마가 하나라도 있다 | 그 스키마의 값 |
| 4 | 없다 | `true` + 알림 |

### 4-5. 조용히 넘기지 않는 것 (알림 · 종료)

| 만난 것 | 처리 |
| --- | --- |
| settings·그룹 파일을 못 찾음 · `m_SerializeEntries`·`m_GroupAssets` 칸이 없음 · 읽어야 할 칸이 모르는 꼴 | **종료 4, 색인 안 씀.** 반쪽 색인은 거짓 통과를 부른다 |
| `m_GroupAssets` 의 guid 가 .meta 표에 없음 (지운 그룹) | 알림, 그 그룹 건너뜀 |
| 항목 guid 가 .meta 표에 없음 (지운 에셋 · `Packages/` 안 에셋) | 알림, **빼지 않고** `path:""`·`kind:"other"` 로 넣는다. 빼면 `Packages/` 에셋을 가리킨 칸이 V10 에서 거짓 오류가 난다 |
| `m_GUID` 가 `EditorSceneList` · `Resources` (옛 Built In Data 그룹) | 알림 없이 건너뜀 — guid 가 아니라 특수 표시다 |
| 같은 address 두 항목 | 알림, 둘 다 넣는다 |
| `.meta` 의 `guid` 가 같은 파일 둘 | 알림, 먼저 본 것 |
| `--out` 이 다른 드라이브 | 알림, `unityRoot` 에 절대 경로 (4-1) |

### 4-6. 폴더 · 시험

```
AssetTool/
  cmd/assettool/        인자 가르기 · 결과 찍기 (index · version)
  internal/unityyaml/   Unity YAML 줄 읽기. Addressables 를 모른다
  internal/meta/        .meta 훑기 → guid 표 · 스프라이트 시트
  internal/addr/        settings·그룹·스키마 읽기. Addressables 칸 이름을 아는 유일한 곳
  internal/index/       계약 꼴 · kind 판정 · 폴더 펼치기 · 정렬 · 쓰기. 계약을 아는 유일한 곳
  Testdata/contract/    address-index.example.json (DataTool 과 같은 바이트, .gitattributes -text)
  Testdata/project/     작은 Unity 뿌리 흉내 (아래)
  README.md · build.ps1 · Docs/
```

**시험 자료 `Testdata/project/` :** 공식 Addressables-Sample 의 Sprite Land 에서 settings·그룹·스키마 `.asset` 몇 장을 줄여 가져오고,
.meta 와 에셋은 손으로 만든다(png 1×1 · wav 짧은 것 · 빈 prefab). 여기에 **2-2 예제가 나오게** 그룹·폴더 항목·스프라이트 시트를 맞춘다.
Addressables 4.0 꼴(`m_IncludeInBuildMigrated: 1`) 그룹 파일 한 장을 따로 둔다. I1 자료는 **Unity 에디터를 한 번 손으로 돌려** 실제로 쓴 YAML 에서 뜬다.

| # | 시험 | 합격 |
| --- | --- | --- |
| I1 | 줄 읽기 | 흐름 맵 · 블록 목록 · 세 가지 따옴표 · 세 꼴의 접힌 줄 · 서로게이트 쌍 · 한글 address |
| I2 | 전체 색인 | `Testdata/project` → **2-2 예제와 바이트가 같다** (시각 칸 고정 · 정렬 · 들여쓰기 · 끝 `\n`) |
| I3 | 폴더 펼치기 | 뺄 것 ①~④ 가 빠지고 · `.asmref` 는 남고 · 따로 있는 항목이 이긴다 |
| I4 | 스프라이트 | Multiple 은 `sub` 둘 · Single 은 없음 · rect 값 · `.psb` 는 시트가 적혀 있어도 `sub` 없음 · Multiple 0칸은 `sub` 없음 · 못 읽은 시트는 쓸 때만 종료 4 |
| I5 | IncludeInBuild | 4-4 표 네 줄 |
| I6 | 알림·종료 | 4-5 표 줄마다 — 종료 4 인 시험은 **파일이 안 생겼는지** 까지 |
| I7 | 같은 입력 두 번 | 같은 바이트 (시각 칸 빼고) · address 가 같은 두 항목은 guid 차례 |
| I8 | settings 찾기 | `EditorBuildSettings` → `DefaultObject` → settings 세 단계 · 중간 칸이 빠지면 기본 자리 |

## 5. 구현하며 정한 것 (2026-10-01)

설계가 비워 둔 자리를 이렇게 메웠다.

| 물음 | 정한 것 | 까닭 |
| --- | --- | --- |
| 모르는 꼴을 어디서 막나 | 값 하나가 모르는 꼴(블록 글 `\|`·앵커·별칭·태그·짝 없는 서로게이트·닫히지 않은 따옴표)이면 그 칸만 「못 읽음」 노드로 두고, **그 칸을 읽을 때** 오류(종료 4). 들여쓰기가 무너지면 파일 전체 오류 | 「읽어야 하는 칸 자리에 나오면」 종료 4 라는 4-2 의 뜻 |
| 꼴이 무너진 `.meta` | `guid:` 줄만 건져 표에 넣고 알림. 다만 `TextureImporter` + `spriteMode: 2` 면 시트를 못 읽은 까닭을 에셋에 들고 있다가, **색인이 그 에셋을 실제로 쓸 때만** 종료 4 (주소에 안 걸린 시트는 그대로 지나간다) | 상관없는 임포터 칸 하나·주소에 없는 그림 하나 때문에 프로젝트 전체 색인이 멈추지 않게 |
| 따옴표 없는 값 안의 ` #` | 자르지 않고 그 칸을 「못 읽음」으로 둔다 (읽으면 종료 4). 따옴표 안의 `#` 은 글자 그대로 | `m_Address: Item #1` 이 `"Item"` 으로 조용히 틀리는 것을 막는다. Unity 가 이런 값을 따옴표로 감싸는지 실물로 보기 전까지의 보수적 선택 |
| 흐름 꼴이 줄을 넘길 때 | 이어지는 줄을 빈칸으로 붙여 다시 읽는다 | 줄바꿈은 흐름 안에서 빈칸과 같다 |
| 짝 파일이 없는 `.meta` | 표에 안 넣고 알림 | Unity 도 경고만 낸다 |
| `.` 으로 시작 · `~` 로 끝나는 폴더 | 훑지 않는다 (meta 훑기·폴더 펼치기 둘 다) | Unity 가 임포트하지 않는 자리라 `.meta` 가 없다 (뺄 것 ①과 같은 결과) |
| 폴더 항목 안에 **따로 항목인 아래 폴더** | 그 아래는 펼치지 않는다 — 아래 폴더 항목이 스스로 펼친다 | 4-3 「따로 있는 쪽이 이긴다」를 폴더에도 같게 |
| `m_IncludeInBuildMigrated: 1` 인데 그룹 `m_IncludeInBuild` 칸이 없다 | 4-4 의 2번 줄로 넘어간다 | 칸이 없는 것은 오류가 아니라 「없다」 |
| 스키마 guid 가 표에 없다 | 그 스키마를 건너뛰고, 그 그룹의 알림에 적는다. 여럿이면 한 줄에 ` · ` 로 잇는다 | 지운 그룹과 같은 다루기 |
| EditorBuildSettings 사슬이 끊겨 기본 자리를 쓸 때 | 알림 한 줄 (어느 단계에서 끊겼나) | 다른 자리에 settings 를 둔 프로젝트에서 엉뚱한 파일을 읽는 일을 사람이 알아채게 |
| `--out` 이 `Assets/`·`ProjectSettings/`·`Packages/` 안 | 쓰지 않고 종료 1 | 「Unity 파일은 한 글자도 안 쓴다」 |
| 링크·junction 을 거친 `--out` · 뿌리 | 둘 다 있는 칸까지 링크를 풀어 실제 자리로 바꾼 뒤 비교한다. Windows junction 은 `filepath.EvalSymlinks` 가 안 풀어서 칸마다 `os.Lstat` 으로 보고 `os.Readlink` 로 따라간다 (40번 넘게 따라가면 오류) | 뿌리 밖 junction 이 `Assets/` 를 가리키면 글자 비교만으로는 못 막는다. 실제 junction 을 만들어 시험했다 |
| 그룹 항목에 `m_Address` 칸이 아예 없다 | 알림 한 줄 내고 `""` 로 넣는다 (종료 4 아님) | 빈 address 와 같은 결과라 색인을 멈출 까닭이 없다. 다만 꼴이 이상하니 사람이 알게 |
| 종료 4 때의 알림 | 그때까지 모은 알림을 stderr / `--json` 의 `notices` 에 싣는다 | 무엇이 먼저 이상했는지가 실패 까닭을 찾는 실마리다 |
| `.psb` | `.meta` 에 시트 칸이 적혀 있어도 `sub` 를 안 만들고 시트 오류도 안 본다 (확장자로 먼저 가른다) | PSD Importer 는 꼴이 달라 시트 칸을 믿을 수 없다 |
| Multiple 인데 자른 칸이 0개 | `sub` 를 안 적는다 | `omitempty` 꼴을 지키려고. 「모른다」로 읽혀 DataTool 이 경고로 통과시킨다 |
| `generator` | `assettool <판> (<커밋>)`, 커밋을 안 박았으면 `dev` | `version` 명령과 같은 값 |
| 시험 자료 `Testdata/project/` | Addressables-Sample 을 안 가져오고 같은 꼴을 손으로 썼다. UI 그룹을 Addressables 4.0 꼴(`m_IncludeInBuildMigrated: 1`, 스키마는 0)로 두어 I2 에서 4-4 의 1번 줄도 탄다. 4-4 네 줄 · 뺄 것 ①~④ 는 시험 코드가 임시 폴더에 만든다 | 라이선스 확인 전 (루트 문서 6절). I1 자료를 **실물 Unity 로 뜨는 일은 아직 못 했다** |
